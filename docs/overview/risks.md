# Risks and the tests that cover them

Each risk of the product requirements has a mitigation in the code and at least one test that fails when the mitigation breaks.

| Risk                        | Mitigation in the code                                                                                            | Test                                                                                                                                                                                                                |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hallucinated information    | Replies cite playbooks, a judge checks groundedness, and the run abstains.                                        | `packages/reply-agent/src/pipeline/pipeline.test.ts`: "escalates an answer for which the agent found no playbook".                                                                                                  |
| Incorrect classification    | Triage escalates below a confidence of 0.6 (product decision 0003), and a reply is a draft that the user reviews. | `packages/reply-agent/src/pipeline/pipeline.test.ts`: "handles a classification with a confidence below the threshold".                                                                                             |
| Incorrect rule execution    | The gate applies the playbook conditions in code, not with a model.                                               | `packages/auto-reply/src/conditions.test.ts` and `apps/worker/src/modules/email-gate/service.test.ts`.                                                                                                              |
| Prompt injection            | The email is wrapped as untrusted data, and the output guardrail blocks leaks.                                    | `guardrails.test.ts`: "keeps the email from closing its envelope". `pipeline.test.ts`: "escalates a draft that the output guardrail blocks".                                                                        |
| Outdated knowledge          | Retrieval keeps only enabled playbooks that are inside their period.                                              | `packages/knowledge/src/usable.test.ts` and `search.integration.test.ts`: "excludes vectors whose row is disabled or expired".                                                                                      |
| Sensitive information leak  | Every query is scoped to the owner, and the vector row is checked again.                                          | `packages/knowledge/src/search.test.ts`: "does not return the row of another user even when its vector claims to be the caller's".                                                                                  |
| Duplicate responses         | Records and queue messages have idempotency keys, and a delivery never repeats.                                   | `packages/inbox/src/inbox.test.ts`: "records an email that is delivered twice once …". `reply-deliver/service.test.ts`: "never calls the provider again for a delivery that started and has no end".                |
| MCP tool misuse             | Session scopes limit the tools, and a write needs the write scope.                                                | `packages/mcp-server/src/endpoint.test.ts`: "rejects a call to a tool outside the granted scopes" and "rejects a write from a session without the write scope".                                                     |
| Email integration failures  | Jobs retry, a delivery records its state, and a failure is visible.                                               | `apps/worker/src/modules/reply-deliver/service.test.ts`: "fails the delivery and the message when the provider refuses the reply". `reply-run/job.test.ts`: "marks the message failed when the last attempt fails". |
| Incorrect period scheduling | Periods are instants with an offset, so a timezone cannot shift them.                                             | `packages/auto-reply/src/status.test.ts` and `apps/api/src/modules/playbooks/playbooks.test.ts`: "a bound without an offset".                                                                                       |
